# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

- **Primary: learners.** CS and ECE students and self-learners who need number-base conversion to be automatic: intro systems, digital logic and computer architecture courses, exams, technical interviews, CTFs. They play in short sessions on a laptop at a desk or on a phone between classes, and come back to beat their own number.
- **Second: teachers.** Instructors who open a live room as a class warm-up or share a drill link in slides or an LMS. Students join as guests on whatever device they have; the room often runs on a projector.
- Casual players who like a daily puzzle are welcome, but copy and structure serve the learner first.

## Product Purpose

Make base conversion (binary, octal, decimal, hexadecimal) and the topics built on it (powers of two, two's complement, bitwise operations, binary addition, hex colours, ASCII) a reflex through timed, typed drills. Success is a player who opens the site, is answering a question within seconds, and returns to improve.

**The game is the product.** The site is a game with a short course attached, not a service being sold. Every page should get a player into a run, or back to one, with as little in between as possible.

## Positioning

Zetamac-style speed drills for number bases: the answer submits itself the moment it is correct, so play is pure typing with no submit button and no mouse. Questions come from a deterministic seeded stream, so a daily challenge and a multiplayer room give every player the same questions. Each topic has a matching lesson with worked, step-by-step solutions in practice mode.

## Operating Context

- First visit: no sign-up; every visitor is an anonymous Firebase user and can play everything, including multiplayer.
- Solo loop: pick a topic and format → countdown → typed answers (Tab skips, Esc pauses) → results with per-question review → replay.
- Daily: the same ten questions for everyone each UTC day; one ranked attempt.
- Classroom: host opens a room (2–10 seats), shares an 8-character code or `/join/<code>` link, everyone readies, host starts, live standings, chat, results.
- Shareable deep links for teachers: `/play?mode=<topic>:<format>`, custom drills via `/play?mode=custom&c=…`.

## Capabilities and Constraints

- 11 topics in four tiers (Foundations, Core, Advanced, Applied) plus custom drills.
- 5 formats: Sprint (60 s, most correct), Speedrun (first to 15, fastest), Survival (3 lives, shrinking clock), Daily (10 questions, one ranked attempt), Practice (untimed, hints and worked solutions, never ranked).
- Leaderboards and synced history need a free account (email/password or Google); guest runs stay in the browser and carry over on sign-up.
- Learn: one interactive lesson per topic.
- No backend code (no Cloud Functions); Firebase Spark-plan limits apply. Strict CSP: no inline scripts, fonts self-hosted, no third-party analytics.
- Question streams must stay deterministic across clients and versions.
- Name: **Based Math Game** (wordmark "Based Math"). Free and open source (GPL-3.0). Inspired by zetamac.

## Brand Commitments

- The brand is **academic: paper, books, school.** The original identity was a textbook / notes / papers theme; the user has made restoring it binding and asked for the full world, not accents. Surfaces read as school artifacts, not SaaS.
- The home screen is a title page with a Play action (in the spirit of Wordle's and other web games' splash screens), not a marketing landing page.
- Voice: plain, specific, a little dry. Numbers over adjectives. No hype, no emoji in UI copy.
- Each number base keeps a stable identity colour and is always labelled, never colour alone.

## Evidence on Hand

- Real product content: topic and format definitions in `src/game`, lessons in `src/features/learn`, How-to-play copy, the daily ladder.
- No testimonials, user counts, school partnerships, press or ratings exist. Do not invent any.
- Brand assets: `public/icon.svg`, `public/og.png` (both generated by scripts in `scripts/`).

## Product Principles

1. **One keypress to play.** From any non-game page, starting or resuming a run is never more than one obvious action away; Enter works where it can.
2. **The run is sacred.** During a run nothing competes with the prompt and the answer field: no chrome, no promotions, no layout shift.
3. **Teach in the margin.** Learning content sits next to play (worked solutions, lesson links), never in front of it.
4. **Same questions, fair race.** Daily and rooms are only meaningful because everyone sees the same stream; never trade that away.
5. **Accounts are optional.** Nothing a guest can do should feel locked behind sign-up except ranking and sync.

## Accessibility & Inclusion

- WCAG 2.2 AA contrast for all text in both themes; keyboard-complete play; visible focus everywhere.
- Touch targets ≥ 44 px; inputs ≥ 16 px on mobile so iOS does not zoom.
- `prefers-reduced-motion` stops all non-essential motion; timers and scores announce politely, not every tick.
- Base identity is never colour alone (always a BIN/OCT/DEC/HEX label).
- Names in any script (ZWNJ/ZWJ allowed); layouts work at 320 px.
